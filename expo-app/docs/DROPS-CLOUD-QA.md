For protected CI runs, use `node scripts/cloud-qa-ci.mjs`. Configure only the dedicated QA job with `DROPS_TEST_SERVICE_ROLE_KEY` (a Drops Test server secret), `DROPS_QA_BROWSER_URL` (immutable test deployment), and the test public URL/publishable key. The runner creates two random confirmed accounts through Auth Admin, runs real user-authenticated RPC checks, resets only their owned test records, runs browser onboarding/corrections/isolation, resets them for deletion checks, and deletes remaining accounts in `finally`. Browser inputs contain disposable identities only; its temporary file is outside the repository and removed even when a gate fails. Output contains pass labels only. Do not reuse fixed CI passwords or expose the admin credential to an Expo export/build step. Store it in a protected EAS QA job environment or protected GitHub environment secret; avoid releasing that job's secrets to untrusted fork pull requests. Prefer a dedicated rotatable Supabase secret key to a legacy service-role JWT. Both are accepted by the Node-only Supabase client.

Current connector access exposes publishable keys only. Secret-key retrieval is unavailable through this MCP catalog, and the local CLI has no management authentication configured. Supplying the protected test credential remains an operational prerequisite; the CI runner fails before network calls with an actionable message when it is missing. No service credential has been retrieved, saved, printed or committed. Existing manual browser fixtures remain reserved for the hosted rerun and are independent of future per-run CI fixtures.
