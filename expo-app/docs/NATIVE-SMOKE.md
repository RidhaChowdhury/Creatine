# Native smoke preparation and execution evidence

## GitHub Actions Android smoke

Root `.github/workflows/android-smoke.yml` accepts a required existing Expo EAS APK URL on manual dispatch. It also permits same-repository PR events only for head branch `codex/drops-v01` when public repository variable `DROPS_PREVIEW_APK_URL` exists; manual input takes precedence. Forks and other branches are excluded. The validator permits only exact `https://expo.dev/artifacts/eas/<identifier>.apk` paths with no query, fragment, shell syntax, alternate host or credentials. It downloads an existing binary and never starts an EAS build. The fixture must use the isolated backend embedded in that binary. Repository read-only checks returned PUBLIC, ADMIN viewer permission, Actions enabled and all actions permitted on 2026-10-04.

Lead creates fresh confirmed-email fixture secrets `DROPS_NATIVE_QA_EMAIL` and `DROPS_NATIVE_QA_PASSWORD` in GitHub, using the same empty-state preconditions below, then pushes and manually dispatches the workflow after the APK completes. GitHub secrets become only `MAESTRO_EMAIL`/`MAESTRO_PASSWORD` process environment variables, never CLI arguments. The display name is generic `Native QA`. One Ubuntu 24.04 hosted API 35 Pixel6 emulator runs, with a 35-minute job limit and no retries or local emulator. The action is pinned to ReactiveCircus v2 commit `a421e43855164a8197daf9d8d40fe71c6996bb0d`; Maestro is pinned to CLI2.11.0 and its release ZIP SHA256 is checked. All helper actions are pinned to commits.

`scripts/native-smoke.mjs` captures Maestro output without printing it, directs raw debug/reports to a temporary workspace, copies only three named post-login screenshots and constructs a fixed-field result summary. It deletes raw temporary artifacts afterward. The upload step targets only `artifacts/native-smoke-safe`, retaining artifacts for three days; raw failure screenshots, logs, command JSON and reports are never uploaded. A failed login produces a generic phase/status summary without credential text. This makes failure diagnosis deliberately limited. If the hosted runner is terminated before cleanup, its ephemeral raw workspace is still outside the artifact upload path. No credential values exist in prepared source or local artifacts.

Reusable fixture: `scripts/native-fixture.mjs` uses built-in fetch, the fixed Drops Test endpoint and a public client key. Before emulator execution it authenticates the fixture, verifies server `getUser` UUID/email/role/audience and `test_fixture:'drops-isolated-qa'`, deletes only the verified owner's rows across eight allowlisted app tables and verifies each is empty. Metadata is an additional disposable-fixture guard; ownership comes from authenticated identity and RLS. The same operation runs in `finally` after the flow, and failed cleanup makes the run fail. Auth account is retained; only reset sessions are logged out locally. No admin credential or production operation is used. A terminated runner may miss final cleanup; the next run's verified pre-reset still prevents stale-history acceptance.

The iOS simulator name can be overridden with the exact device listed by the selected worker image. The proposed iPad name has not been observed on that image yet; schema validation cannot establish device availability.

Create a fresh confirmed-email fixture account in the isolated test backend before each run. It must have no intake, no configured water target and the default prominent 8 oz preset. Store `MAESTRO_EMAIL`, `MAESTRO_PASSWORD` and `MAESTRO_NAME` only as sensitive/secret variables in EAS's preview environment. Do not put values in workflow inputs, source, command lines, screenshots or committed artifacts. Fixture names must be ASCII for Android input support. Do not use production accounts. Reusing an account fails the empty History precondition rather than silently accepting pre-existing water records; retries are disabled to prevent duplicate intake. Remove the fixture account after evidence is reviewed.

The flow checks login, name-only onboarding when shown, primary navigation, empty History, one 8 oz water write, exact History entry, application termination/relaunch, retained session and retained History. It does not clear local state during the persistence relaunch. Named screenshots are taken only after login, never while email/password are entered. EAS publishes Maestro reports automatically; sensitive EAS values are redacted in workflow logs, but raw Maestro failure/debug artifacts must be treated as credential-bearing until reviewed. Before sharing or copying artifacts, remove login screenshots and redact any resolved input values. No screen recording is requested. Artifact secrecy across third-party report formats has not been verified by source preparation.
