# Local browser verification

Run from `expo-app` using Node22. Start `npm run dev:local` in a background terminal, then run `npm run test:e2e`. The default URL is `http://localhost:8082`; no server is launched implicitly. One headless Chromium worker uses fresh isolated contexts. The config rejects external hosts and production ports; fixtures block all Supabase hosts. These tests create only synthetic SQLite records inside their disposable browser contexts.

For a local-backend web export served on4173, set `DROPS_E2E_URL=http://localhost:4173` before running. The export must have been built with the local environment. The preview serves COOP/COEP headers, CanvasKit, fonts and SQLite worker/WASM assets. A cloud bundle cannot pass these tests because its connections are blocked; use the separately guarded opt-in cloud suite for cloud verification.

`npm run test:e2e` covers name-only onboarding, real CanvasKit, navigation, quick water/persistence/reload, exact deletion/restore amid newer entries, historical90day/custom ranges, cancelled edits, custom medication schedules/profiles/archive, and draft retention across320/390/797/1440 viewport resize. All actions use accessible selectors and readiness assertions; there are no arbitrary waits.

`npm run test:visual` runs actual reduced-motion Skia capture checks. The first intentional baseline creation is `npm run test:visual -- --update-snapshots`. Review every generated image before accepting it. Baselines cover real zero/partial/full water states and typography at the four requested sizes. The0.2% pixel threshold is intentionally narrow and must not be enlarged to hide layout defects. Baselines are specific to the checked-in Playwright Chromium version/platform. Viewport resizing verifies browser layout behavior; it does not establish native iPadOS multitasking, keyboard, pointer or VoiceOver behavior.

Failure PNGs, traces and report files are in `artifacts/e2e-results` and `artifacts/e2e-report`. They contain synthetic local fixtures; never run automatic screenshot tests against a real production account. The report does not open a browser window. Rendering tests do not validate readiness prediction, cloud RLS or physical-device behavior.

Water visual tests decode the actual composited page PNG with `pngjs` and assert blue water pixels before comparing a golden. Full water also requires a readable WATER label region and dark submerged number strokes with blue counter holes. The app requests a preserved WebGL buffer; the tests verify that browser setting and require three identical painted frames before accepting a capture. A DOM total, an attached canvas, or WebGL `toDataURL()` alone cannot pass this gate, and a stale black capture must fail even if it matches a previously generated image.

Headless Chromium explicitly uses ANGLE SwiftShader (`--use-gl=angle --use-angle=swiftshader`) for deterministic software rendering. Merely allowing unsafe SwiftShader fallback left hardware compositing enabled and produced duplicated background tiles on this Windows GPU while gaming. Both rendering paths used the same strict pixel checks; the software path is the reproducible CI baseline, while actual in-app browser/device rendering remains a separate manual check.

Visual CI uses Windows with the pinned Chromium revision and the reviewed `*-win32.png` baselines. Linux runs the functional suite. Keep platform-specific baselines: DirectWrite/FreeType text differences must be reviewed on the actual platform before adding Linux goldens. A missing platform baseline is a failing/unmet visual gate; CI must never use `--update-snapshots` or silently accept it. Startup has a120second total test budget and60second onboarding readiness for cold Metro worker compilation; action assertions stay20seconds. The deterministic clock starts at2026-10-04T17:00Z and advances normally so native timing animations can settle.
